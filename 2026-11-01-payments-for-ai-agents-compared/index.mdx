An AI agent needs one data lookup. The price is $0.001. Before the provider can return a result, the agent needs a way to pay that leaves the sale worth making.

We build Atto for [small, direct agent payments](/agent-payments) with no protocol transfer fees, first-party MCP, CLI and n8n integrations, and public node access. Its wallet tools are available today. A complete paid-HTTP service still needs custom payment logic.

USDC tracks the dollar and carries issuer and redemption conditions. [USDC terms](https://www.circle.com/legal/usdc-terms).

USDC has x402 support, with routes that settle each payment individually and routes that batch settlement. Lightning serves bitcoin payments through L402. Nano offers another feeless option with community agent tools. For AI agent micropayments, the useful choice depends on the service, the payment size and the integration you want to run.

**Why chained latency matters.** If the next request waits for the previous payment, 100 waits of 150 ms add 15 seconds. At 300 ms they add 30 seconds. A wallet doing nothing else can complete twice as many serial payments at the shorter interval. Signing, network round trips and the API’s own work add time. A seller who needs to spend each incoming payment may also have to wait beyond the point when it can release the response.

The [agent-payment guide](/docs/integration/agent-payments) walks through a first bounded Atto payment and shows where confirmation fits into an API purchase.

## When a $1 workload leaves nothing to run the service

**1,000 calls at $0.001 each earn $1.** Once Coinbase CDP's monthly free allowance is used up, one successful `exact` settlement per call costs **$0.001**. Those 1,000 additional calls incur **$1 in fees and leave $0 before service costs**. The first 1,000 monthly onchain facilitator transactions are free. Verification is free and the settlement fee covers gas. [CDP pricing](https://docs.cdp.coinbase.com/x402/seller/facilitator#pricing), [pricing FAQ](https://docs.cdp.coinbase.com/x402/support/faq#cost-and-money-movement).

At the same tariff, the fee takes 10% of a $0.01 sale or 1% of a $0.10 sale. For cheaper calls, compare Circle Gateway Nanopayments and Coinbase CDP's EVM batching scheme before choosing a route. For direct Atto and Nano transfers, include funding, conversion and infrastructure when working out the cost.

## What each option offers

### Atto: feeless payments with first-party agent tools

Atto suits individual payments where a protocol fee would consume too much of the sale. The first-party [MCP](/build/mcp), [CLI](/build/cli) and [n8n](/build/n8n) tools use public services, so developers can start without finding or hosting a node.

The CLI/MCP wallet starts read-only and lets you approve [per-payment and rolling spending limits](/docs/integration/mcp#approve-a-spending-allowance) locally. Those packages are in beta. A complete paid-API flow still needs custom quoting, payment matching and delivery logic. The [x402-style flow and demonstration endpoint](/docs/roadmap#phase-7-micropayment-rails) remain planned work.

### Nano: feeless payments with community integrations

Nano also fits small, direct payments. Its community [Feeless402 CLI/MCP](https://github.com/Feeless402/feeless402) provides public RPC defaults, and [Nano's agent page](https://nano.org/agents) links x402 tooling. Running your own node is optional.

The setup score covers Feeless402. Its settlement result reports the block hash and confirmation state separately. The seller needs to check that state before delivering the purchase. [Feeless402 settlement result](https://github.com/Feeless402/feeless402/blob/4dd6d7abca767981552bc74e88f7f434b760ea0d/nano_pay/verify.py#L198-L229).

### USDC on Base: dollar pricing and existing x402 support

USDC on Base fits services that price in dollars and already support x402. The [client SDK](https://docs.x402.org/getting-started/quickstart-for-buyers) and hosted facilitator provide a paid-HTTP path without operating a Base node.

On November 5, 2026, Base's Denim upgrade replaced Flashblocks with native blocks at a 200 ms cadence. A receipt becomes available after inclusion in a canonical Base block. The block becomes safe when its batch is posted to Ethereum and final when Ethereum finalizes that batch. Choose which stage your service requires before delivery. [Base Denim announcement](https://www.base.org/blog/denim), [receipt migration guide](https://docs.base.org/upgrades/denim/migrate-from-flashblocks).

### USDC on Solana: dollar payments for Solana services

USDC on Solana serves the same dollar-pricing need through another network. It is useful when the seller and agent already use [compatible Solana x402 tooling](https://docs.x402.org/core-concepts/network-and-token-support).

Configure the wallet and recipient token accounts for that path. Native transfers have network fees, which CDP covers through the same `exact` tariff as on Base. CDP's batching scheme supports EVM chains. Its Solana routes use `exact` or `upto`. [CDP supported networks](https://docs.cdp.coinbase.com/x402/seller/facilitator#advanced).

### USDC through Circle Gateway Nanopayments

Circle launched Gateway Nanopayments on mainnet on April 29, 2026. Buyers deposit USDC into a non-custodial Gateway contract and sign offchain for individual payments as small as $0.000001. This route requires signatures from an externally owned account. Buyers can use Circle's CLI or SDK, and sellers can use its x402 middleware on Base and other supported EVM chains. [Mainnet launch](https://www.circle.com/blog/nanopayments-powered-by-circle-gateway-is-now-live-on-mainnet), [Circle developer guide](https://developers.circle.com/gateway-nanopayments), [supported networks](https://developers.circle.com/gateway-nanopayments/supported-networks).

Gateway checks the authorization against the buyer's balance. The seller can serve the request once Gateway accepts payment. Circle uses a trusted execution environment to validate and batch authorizations, and the seller's balance becomes spendable after the batch settles onchain. Reconcile accepted requests against Gateway's settlement records. [Settlement model](https://developers.circle.com/gateway-nanopayments/concepts/batched-settlement), [seller reconciliation](https://developers.circle.com/gateway-nanopayments/howtos/x402-seller-reconciliation).

Each authorization is gas-free. Direct funding deposits use onchain gas, and withdrawal costs depend on the route. Circle's Agent Wallet fee schedule lists no Gateway protocol fee for same-chain x402 payments and 0.5 basis points for crosschain x402 payments. It also describes the gas sponsorship and deposit options for that wallet. [Buyer quickstart](https://developers.circle.com/gateway-nanopayments/quickstarts/buyer), [Agent Wallet fees](https://developers.circle.com/agent-stack/agent-wallets/fees), [Gateway fees](https://developers.circle.com/gateway/references/fees).

### USDC through Coinbase CDP batch settlement

CDP's `batch-settlement` scheme uses a funded payment channel. Buyers sign offchain vouchers that a seller can claim together. After the free allowance, the $0.001 tariff applies to each onchain batch claim and each onchain channel operation such as a deposit, refund or withdrawal. Offchain verification is free. A claim records the amount owed. A separate settlement call transfers the funds to the seller. This spreads the claim fee across many calls. [Batch claim and settlement](https://github.com/x402-foundation/x402/blob/main/specs/schemes/batch-settlement/scheme_batch_settlement_evm.md#claim--settlement-strategy), [CDP pricing and supported networks](https://docs.cdp.coinbase.com/x402/seller/facilitator).

CDP's facilitator supports the scheme on Base and other EVM chains. Its `createX402Server` helper currently leaves the scheme unregistered, so the seller needs an integration that handles the channel and claims the vouchers. Circle Gateway uses x402 `exact` with Gateway-specific signing requirements. [CDP scheme guidance](https://docs.cdp.coinbase.com/x402/support/faq#pricing-and-payment-schemes), [Circle x402 seller guide](https://developers.circle.com/gateway-nanopayments/howtos/x402-seller).

### Bitcoin Lightning: paid access through a Lightning wallet

Lightning fits bitcoin services using [L402](https://docs.lightning.engineering/the-lightning-network/l402/l402). Lightning Labs' [lnget CLI/MCP](https://github.com/lightninglabs/lnget) can pay a challenge and retry the request. [Alby MCP](https://github.com/getAlby/mcp/) connects agents and n8n workflows to a compatible wallet.

Aperture’s static endpoint price is a whole number of satoshis. At the November 2 BTC quote, $0.001 bought about 1.28 sats, so a seller charging per request would have to round the price. [Aperture price configuration](https://github.com/lightninglabs/aperture/blob/1f2e5a1e98adf743bc6e0765bc638d2f20c11ade/proxy/service.go#L116-L118).

On a funded direct channel to the seller there is no intermediary to charge a forwarding fee. If a 1-sat invoice instead takes a route with a total 1-sat fee, the sender spends 2 sats to deliver 1. Both examples assume the route accepts the invoice and there is no separate wallet-provider charge. Each forwarding node sets its own base fee and proportional rate. [Lightning channel fees](https://docs.lightning.engineering/the-lightning-network/pathfinding/channel-fees).

In November 2026, Megalith published wallet records for five mainnet transfers of **1,000 sats** each. Senders paid **4–8 sats** per transfer. Those receipts show how fees vary by route and wallet at that amount. The Lightning fee score uses the smaller **0–100 sat** group in the Fidelity–Voltage report. It contains no separate fee figure for a 1-sat invoice. [November wallet receipts](https://docs.megalithic.me/guides/best-bitcoin-wallets/#how-we-tested), [Fidelity–Voltage fee and timing data, pp. 9–10](https://www.fidelitydigitalassets.com/sites/g/files/djuvja3256/files/acquiadam/FDA_TheLightningNetwork_ExpandingBitcoinUseCases_1187503.1.0_V5.pdf#page=9).

A wallet provider can remove the need to run your own node. Self-hosting adds channel and liquidity management. Routing and provider fees vary. [Alby paid MCP](https://github.com/getAlby/paidmcp).

## Start with the purchase

Choose a payment option the service accepts, then test a small purchase and its timeout recovery. A prepaid service balance may also be simpler when calls can be metered internally.

To try Atto, follow the [agent-payment guide](/docs/integration/agent-payments) for a first bounded payment. The [integration guides](/docs/integration) help you choose MCP, CLI or n8n; the [faucet](/faucet) can fund a small wallet. A paid service must connect payment confirmation to its own purchase and delivery flow.

**Per-call fees.** Divide the fee by the amount paid. For the priced routes we use a $0.001 sale. Lightning uses the reported mean fee percentage for its smallest published payment-size group. Zero earns 5. A positive fee up to 1% earns 4, over 1% through 10% earns 3, over 10% but below 100% earns 2, and 100% or more earns 1. An individual Lightning payment needs a route quote. The example starts after funding and after CDP's monthly allowance. It assumes one batch claim for all 1,000 vouchers. Deposits, withdrawals, conversion, liquidity and running the service affect the full cost.

**Paid API setup.** These are editorial ratings of the named buyer and seller tools. A documented client and seller integration with managed payment infrastructure earns 5. A packaged client and seller proxy with a seller-operated payment backend earns 4. Seller tooling that needs application code to verify confirmation or manage a payment channel earns 3. Wallet tools that leave the paid-HTTP flow to the seller earn 2. A route that also needs a custom wallet client would earn 1. The scores describe the work to integrate the named tools. **Implementation notes.** A wallet tool, a payment network and a paid-HTTP protocol handle different steps. [x402](https://docs.x402.org/core-concepts/http-402) requests payment through HTTP 402. [L402](https://docs.lightning.engineering/the-lightning-network/l402/l402) uses a Lightning invoice and payment proof. For Atto or Nano, match the confirmed send's recipient, amount and purchase before delivery. Check existing payment status after a timeout before starting another payment.

- **Atto MCP** uses public service defaults, operator-approved spending limits, structured payment states and request-ID reconciliation. Those limits apply to the CLI/MCP wallet profile. n8n signing credentials have their own configuration. [Service defaults](https://github.com/attocash/integrations/blob/main/atto-cli/src/wallet/defaults.ts), [payment workflow](https://github.com/attocash/integrations/blob/main/atto-cli/src/spending/payments.ts), [n8n signing configuration](/docs/integration/n8n#enable-signing-only-where-it-is-needed).
- **Feeless402 MCP** supplies public RPC defaults. Its tool price cap is set by the agent. The Nano x402 helper takes an RPC URL. [Price cap](https://github.com/Feeless402/feeless402/blob/4dd6d7abca767981552bc74e88f7f434b760ea0d/nano_pay/mcp_server.py#L107-L118), [x402 helper](https://github.com/x402nano/helper), [Nano integration guide](https://docs.nano.org/integration-guides/).
- **AgentKit on Base and Solana** can use CDP account policies configured separately for the wallet. Its reviewed transfer tools return transaction identifiers. Use those identifiers to check payment outcomes before retrying. [AgentKit](https://github.com/coinbase/agentkit), [EVM policy definitions](https://github.com/coinbase/cdp-sdk/blob/3a566571c8c9d7c1b00eb3a47e6a7755ab786fe7/typescript/packages/cdp-sdk/src/policies/evmSchema.ts), [Solana policy definitions](https://github.com/coinbase/cdp-sdk/blob/3a566571c8c9d7c1b00eb3a47e6a7755ab786fe7/typescript/packages/cdp-sdk/src/policies/solanaSchema.ts).
- **Alby MCP with a self-operated Hub** provides wallet budgets, payment lookup and same-invoice duplicate protection. Lightning self-hosting also needs inbound and outbound liquidity. [Hub setup](https://guides.getalby.com/user-guide/alby-hub/faq/where-is-alby-hub-physically-located), [payment handling](https://github.com/getAlby/hub/blob/master/transactions/transactions_service.go), [Lightning liquidity](https://docs.lightning.engineering/the-lightning-network/liquidity/how-to-get-inbound-capacity-on-the-lightning-network).

Direct Base transfers have execution and publication fees. On Solana, the fee payer can differ from the sender and a new token account requires a refundable storage deposit. [Base network fees](https://docs.base.org/specifications/transactions/network-fees), [Solana fee payer](https://solana.com/docs/payments/how-payments-work), [Solana token accounts](https://solana.com/docs/tokens/basics/create-token-account).
